# Duka Smart Electronics – Retail Sales & Customer Intelligence Using PostgreSQL

## 1. Project Overview

This project focuses on analysing retail sales and customer data for Duka Smart Electronics using PostgreSQL.

The main goal is to use SQL to understand business performance, identify customer purchasing patterns, analyse product performance, and generate insights that can help management make better business decisions.

The project uses a relational database containing customer and order information.

## 2. Business Objectives

The analysis aims to:

- Identify the highest-spending customers.
- Analyse revenue and profit generated by different products and categories.
- Understand customer purchasing behaviour.
- Compare sales performance across different cities.
- Analyse monthly revenue trends.
- Identify inactive customers.
- Segment customers according to their spending.
- Provide recommendations that can improve sales and profitability.

## 3. Database Information

**Database name:** `retail_analytics`

**Schema:** `retail`

The database contains two main tables:

### Customers Table

Stores information about customers.

| Column | Description |
|---|---|
| customer_id | Unique customer identification |
| customer_name | Customer's full name |
| gender | Customer gender |
| city | Customer location |
| registration_date | Date the customer registered |
| customer_segment | Customer category or segment |

### Orders Table

Stores information about customer purchases.

| Column | Description |
|---|---|
| order_id | Unique order identification |
| customer_id | Customer who made the order |
| order_date | Date the order was placed |
| product_name | Name of the purchased product |
| product_category | Product category |
| quantity | Number of units purchased |
| unit_price | Selling price per unit |
| cost_price | Cost per unit |
| discount | Discount percentage |
| order_status | Order status |
| payment_method | Payment method used |

### Database Relationship

The two tables are connected through `customer_id`.

- One customer can have multiple orders.
- Each order belongs to a customer.
- The relationship is one-to-many.

## 4. Business Rules and Calculations

The following calculations are used throughout the project.

**Revenue**

`Revenue = Quantity × Unit Price × (1 - Discount / 100)`

**Total Cost**

`Total Cost = Quantity × Cost Price`

**Profit**

`Profit = Revenue - Total Cost`

**Profit Margin**

`Profit Margin = (Profit / Revenue) × 100`

### Additional Rules

- Only completed orders are included in revenue, cost, profit and spending calculations unless a question specifies otherwise.
- Order counts include all order statuses unless otherwise specified.
- Customer counts use distinct customer IDs where necessary.
- Discounts are stored as percentages. For example, 10 represents 10%.
- Monthly analysis uses both the year and month to avoid mixing the same month across different years.
- The latest date in the dataset is used when analysing customer inactivity.
- Monetary values are rounded to two decimal places.

## 5. SQL Analysis Sections

The project contains 46 SQL questions divided into six sections.

### Section A: SQL Fundamentals (Q1–Q10)

Covers basic SQL operations, including:

- Retrieving records.
- Selecting specific columns.
- Filtering using `WHERE`.
- Sorting records.
- Finding unique values.
- Using `LIKE`, `BETWEEN` and `IN`.

### Section B: Aggregation and Grouping (Q11–Q20)

Focuses on summarising business data using:

- `COUNT()`
- `SUM()`
- `AVG()`
- `MIN()`
- `MAX()`
- `GROUP BY`
- `HAVING`

The section analyses customer counts, order counts, revenue, product prices, category performance and cancelled orders.

### Section C: Joins and Customer Analytics (Q21–Q28)

Uses table relationships to analyse customer and order information.

Topics include:

- `INNER JOIN`
- `LEFT JOIN`
- Customer spending.
- Customers who have never ordered.
- Highest-spending customers.
- Customer activity by segment.
- Popular product categories.

### Section D: Subqueries and CTEs (Q29–Q34)

Introduces more advanced query structures.

Topics include:

- Subqueries.
- Common Table Expressions (CTEs).
- Average customer spending.
- Monthly revenue analysis.
- Customer purchasing patterns.
- Inactive customer identification.

### Section E: Window Functions (Q35–Q42)

Uses window functions to perform advanced analysis.

Topics include:

- `RANK()`
- `ROW_NUMBER()`
- `DENSE_RANK()`
- `NTILE()`
- `LAG()`
- Cumulative revenue.
- Monthly revenue growth.
- Revenue contribution by category.

### Section F: Advanced Business Intelligence (Q43–Q46)

Applies SQL to create reusable analytical outputs.

Topics include:

- Creating a monthly sales summary view.
- Creating a PostgreSQL function.
- Customer value segmentation.
- Preparing a management report.

## 8. How to Run the Project

1. Install PostgreSQL and DBeaver Community Edition.
2. Connect to the PostgreSQL server.
3. Create or connect to the `retail_analytics` database.
4. Create the `retail` schema.
5. Execute the table creation scripts.
6. Insert the customer and order data.
7. Verify that the tables and records have loaded correctly.
8. Open `queries.sql` and execute the questions.
9. Review the query results and document important findings.

## 10. Conclusion

This project demonstrates how PostgreSQL can be used to transform raw retail data into useful business information.

Through SQL queries, joins, aggregations, CTEs, window functions, views and stored functions, the project aims to provide a clearer understanding of customer behaviour, sales performance and business profitability.

The final objective is not only to retrieve data but also to use the results to support better business decisions.
